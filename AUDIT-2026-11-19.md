# Audit — 2026-11-19

Full pass before 0.12.9: security, correctness, hygiene, docs, and what the gates already cover. Every finding names the file and the case, and every fix has a test.

## Verdict

**Ship.** Three security findings, all fixed here. No data-loss bug, no secret in the tree, no dependency.

## Findings

| # | Severity | Finding | Where | Fixed |
|---|---|---|---|---|
| 1 | **High** | `Access-Control-Allow-Origin: *` on every response. A gateway on `127.0.0.1` is reachable by any page the user has open; the Host-header guard does not stop it, because such a page sends the allowed Host. Any website could read answers and spend quota. | `apps/gateway/src/server.js` | Cross-origin denied by default; `server.corsOrigins` is opt-in. Node clients ignore CORS, so nothing else breaks. |
| 2 | **High** | The prober fetched whatever `base_url` the catalogue named — including `http://169.254.169.254/` (cloud metadata) and `http://127.0.0.1:6379`. A seeded or imported entry could make the user's machine fetch its own metadata and report it as a provider's health. | `packages/prober/src/index.js` | `probeAddressAllowed()`: https only, and no loopback, link-local, private, ULA or `.internal`/`.local` host. `allowLocal` is the explicit opt-in (`sui probe <name>`, `sui local`, test fixtures). |
| 3 | **Medium** | Serving on a non-loopback host with no API keys is an open relay: anyone who can reach the port spends your quota. Nothing said so. | `apps/cli/src/cli.js` | Refuses to start with a message naming both ways out; `--allow-open` proceeds with a warning. |
| 4 | Low | `--headless` added to the config schema did nothing — `normalizeConfig` drops unknown keys and it landed in the wrong return block. | `packages/core/src/config.js` | Fixed in 0.12.8; the HTTP-level test is what caught it. |
| 5 | Low | The publish job dirtied the tree its own publisher checks (`evals/last-report.json`, then `package-lock.json`). | `.github/workflows/publish.yml`, `scripts/publish.mjs` | Generated files are named, not counted as edits. |

## What this audit did not do

- **No dynamic analysis of a hostile provider.** A provider that returns malformed SSE, huge headers or a slowloris body is handled by code paths covered by unit tests, not by a fuzzer.
- **No penetration test of the sandbox.** `packages/sandbox` runs 14 attack cases in a separate process; whether the namespace isolation holds on a given kernel is not something this repository can assert.
- **No review of the vendored kits.** They are PolyForm NC upstream and are executed in a `node:vm` context (ADR-0007); their internals were not audited line by line.
- **No claim about the registry.** Published tarballs carry provenance, but what npm serves is npm's to secure.
