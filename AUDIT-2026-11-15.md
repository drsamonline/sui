# Audit — 2026-11-15

A second audit, at commit `main` after Phase 5 (MCP both directions, bounded runs, the two-plane split) and Phase 2's offline half. Same method as the first: `scripts/audit.mjs` for the mechanical claims, plus a security read of the request path.

**Verdict: the code is in better shape than the documentation was.** Four guarantees had shipped as prose and are now invariants with proofs. One real hardening fix came out of the security read. Nothing found is hidden.

---

## 1. Four guarantees were prose, now invariants

The repository's central discipline is that every claim has an enforcement point and a test. Four batches shipped behaviour that was documented but not *claimed* in the invariant table — which means nothing would have failed if it stopped being true.

| Invariant | Claim | Enforcement | Proof |
|---|---|---|---|
| **I16** | An agent plane holds no provider credential, and cannot route | `planes.js planePolicy()` — role `agent` reports `holdsProviderCredentials: false`, and the chat path forwards instead of routing | `test/planes.test.js` |
| **I17** | A bounded run cannot exceed spend, steps, wall clock or a repeated call | `runs.js RunTracker.check()` before the call, `record()` after | `test/runs.test.js` |
| **I18** | A free target ranks before a paid one, whatever order it was declared in | `router plan()` sorts by `tierRank` before any strategy ordering | `test/tier-order.test.js` |
| **I19** | The health history holds no prompt content, and drops any row that carries it | `history.js` — `SAMPLE_FIELDS` is the whole shape, extra fields discarded on load | `test/history.test.js` |

The count assertion in `test/invariants.test.js` is deliberate: adding an invariant now fails the build until the enforcement and the proof exist.

## 2. Security read of the request path

| Question | Finding |
|---|---|
| Is user input ever used to build a filesystem path? | **No.** The only file reads are a fixed dashboard path, a fixed eval report (env-overridable, not request-controlled), and the ledger/history files chosen at startup. |
| Are secrets compared in constant time? | **Yes**, in both places that compare them: `verifyApiKey` (SHA-256 + `timingSafeEqual`) and `tokenMatches` (plane service token). The length-mismatch branch still runs a comparison, so the timing does not reveal length. |
| Is there dynamic code execution? | **None.** No `eval`, no `new Function` anywhere in `apps/` or `packages/`. The kit loader uses `node:vm` with a 5s timeout and an explicit global list (ADR-0007). |
| Is the request body bounded? | **Yes**, 20 MB, rejected before parsing. |
| Are secrets logged? | **No.** Keys are stored as hashes and referred to by name; the CLI prints provider names, never key material. |
| Is the host header checked? | **Yes** (I15) — a forged `Host` is refused, which is what stops a DNS-rebinding page reaching the loopback API. |

### The one real fix

`POST /api/compress` accepted up to 20 MB and then ran six compression engines over it on the event loop. That is a CPU denial-of-service with a single request, on an endpoint whose only purpose is a preview. **Now capped at 200,000 characters**, returning `413 text_too_long`, with a test that sends 250 KB and expects the refusal.

## 3. Accepted risks, stated rather than buried

| Risk | Why it is accepted | Mitigation available |
|---|---|---|
| `/api/*` is unauthenticated by default | the gateway binds loopback and is meant for one machine; forcing a token on a local dashboard makes it worse to use | `apiKeys` for `/v1`, `SUI_ADMIN_TOKEN` for the tenant console, and `role: agent` + a plane token when it faces anything |
| The rate limiter is per-process, in memory | one process is the supported shape; a shared limiter needs shared state (B1.4) | documented; multi-process is deferred by ADR-0001 |
| MCP token counts are estimated (chars ÷ 4) | the protocol reports no usage | labelled an estimate in the docs and in the ledger |
| `llmlingua_2` and `ccr` are approximations | they are useful and they are not what their names suggest | labelled everywhere they appear |
| The embedding tier is feature hashing, not a learned model | it catches near-duplicates, not paraphrase | labelled; a real model needs a provider and quota |
